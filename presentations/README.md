# پذیرش پروژه‌های مهندسی اینترنت

## از یک مسئلهٔ واقعی تا یک محصول قابل ارائه

در این درس، پروژه فرصتی است برای به‌کارگیری مفاهیم مهندسی اینترنت در طراحی و پیاده‌سازی یک راه‌حل واقعی. مسیر پروژه با معرفی و دفاع از ایده آغاز می‌شود و در ادامه به طراحی فنی، پیاده‌سازی و ارائهٔ محصول می‌رسد.

<blockquote>
**مرحلهٔ اول: تحویل Pitch Deck**

مهلت ارسال: **۱۸ آذر ۱۴۰۵**

هر گروه باید ایدهٔ خود را در قالب یک فایل PDF معرفی کند. ثبت پروژه به‌معنی پذیرش آن نیست؛ شروع رسمی کار منوط به تأیید مدرس است.
</blockquote>

## شرایط تشکیل گروه

- هر گروه دقیقاً **۳ نفر** دارد.
- تشکیل گروه و انتخاب اعضا بر عهدهٔ خود دانشجویان است.
- یک نفر به نمایندگی از گروه، پروژه را در GitHub ثبت می‌کند.
- مشخصات و نام کاربری GitHub هر سه عضو باید در فرم ثبت پروژه درج شود.
- اطلاعات ثبت‌شده و فایل ارائه برای همه قابل مشاهده خواهد بود.

## مراحل پروژه

1. **معرفی ایده و Pitch Deck** — مسئله، کاربران، راه‌حل و امکان‌پذیری اولیهٔ آن را معرفی کنید.
2. **بررسی و تأیید** — مدرس ایده و ارائه را بررسی می‌کند. ممکن است پروژه تأیید شود یا برای اصلاح بازگردد.
3. **طراحی و برنامه‌ریزی فنی** — معماری، فناوری‌ها، اجزای سیستم و برنامهٔ توسعه را مشخص کنید.
4. **پیاده‌سازی و ارائهٔ نهایی** — محصول را توسعه دهید، دمو کنید و از تصمیم‌های مهندسی خود دفاع کنید.

جزئیات مراحل بعدی متناسب با پیشرفت پروژه‌ها اعلام خواهد شد.

## راهنمای تهیهٔ Pitch Deck

Pitch Deck یک ارائهٔ کوتاه و منسجم برای معرفی یک ایده و متقاعدکردن مخاطب دربارهٔ ارزش و امکان‌پذیری آن است. در این مرحله انتظار نمی‌رود محصول ساخته شده باشد؛ انتظار می‌رود مسئله را خوب شناخته باشید و برای ساخت راه‌حل، فکر اولیه و قابل دفاعی داشته باشید.

ساختار پیشنهادی:

| بخش | پرسشی که باید پاسخ دهید |
| --- | --- |
| مسئله (Problem) | چه مسئله‌ای وجود دارد و چرا مهم است؟ |
| کاربران هدف (Target Users) | چه کسانی با این مسئله روبه‌رو هستند؟ |
| راه‌حل (Solution) | راه‌حل پیشنهادی شما چیست؟ |
| ارزش پیشنهادی (Value Proposition) | چرا این راه‌حل ارزشمند است؟ |
| محصول (Product) | قابلیت‌های اصلی محصول چیست؟ |
| فناوری (Technology) | از چه فناوری‌ها و ابزارهایی استفاده می‌کنید؟ |
| معماری اولیه (Architecture) | اجزای اصلی سیستم و ارتباط آن‌ها چگونه است؟ |
| امکان‌پذیری (Feasibility) | مهم‌ترین چالش‌ها و ریسک‌های فنی چیست؟ |
| نقشهٔ راه (Roadmap) | چگونه و در چه مراحلی آن را پیاده‌سازی می‌کنید؟ |
| تیم (Team) | اعضای گروه چه کسانی هستند و نقش‌های اولیه‌شان چیست؟ |

### نکات مهم در آماده‌سازی

- مسئله را دقیق و مشخص بیان کنید؛ از معرفی یک ایدهٔ کلی شروع نکنید.
- مخاطب و کاربر واقعی را مشخص کنید؛ «همه» معمولاً پاسخ مناسبی نیست.
- قابلیت‌ها را با راه‌حل و مسئله مرتبط نگه دارید.
- برای ادعاهای مهم از نمونه‌های واقعی، داده، تحقیق یا محصول مشابه استفاده کنید.
- بخش فنی باید نشان دهد که مسیر ساخت محصول را می‌شناسید؛ صرفاً نام فناوری‌ها را فهرست نکنید.
- ارائه کوتاه، خوانا و روایت‌محور باشد. هر اسلاید یک پیام اصلی داشته باشد.
- از کپی‌کردن قالب‌های استارتاپی بدون توجه به ماهیت پروژه خودداری کنید.

## امتیاز تشویقی

از میان **۶ گروه اولی که ثبت‌نام کامل و فایل PDF خود را تحویل دهند**، **۳ گروه برتر** بر اساس کیفیت شناخت مسئله، ارزش راه‌حل، امکان‌پذیری فنی و کیفیت ارائه انتخاب می‌شوند و امتیاز تشویقی دریافت می‌کنند.

زودتر ارسال‌کردن فقط شرط ورود به این ارزیابی است و به‌تنهایی امتیاز یا برتری محسوب نمی‌شود. ملاک ترتیب، زمان ثبت یک درخواست کامل همراه با فایل PDF است.
